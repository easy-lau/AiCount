## 1. Requirements Summary

Add a **Stats page** to the existing Session Manager app that quantifies how much code Claude / Codex have generated by re-parsing the raw session JSONL files. Gemini is **out of scope** because its session data does not record code-write operations.

**Metric:** LOC delta = lines added (`+`) and lines removed (`−`), aggregated by:
- Provider (Claude vs Codex)
- Project (sessions group by `cwd`)
- Time window (all-time / this-month / this-week)
- Top files (sorted by net LOC)

**UI form:** dedicated `Stats` page reachable from a new sidebar tab. The existing session list is unchanged.

**Non-goals (v1):**
- No language-detection breakdown (extension-based grouping can come later)
- No file-extension filter (`.md` / `.txt` are counted; user can refine later)
- No Gemini support
- No timeline chart (just numeric breakdowns + horizontal bars)
- No persistent cache to disk (in-memory cache keyed by file mtime is sufficient)

## 3. Implementation Steps

### 3.1 Backend — new module `src-tauri/src/code_stats/`

**File: `src-tauri/src/code_stats/mod.rs`**

```rust
pub mod claude;
pub mod codex;

use serde::Serialize;
use std::collections::HashMap;

#[derive(Debug, Clone, Default, Serialize)]
#[serde(rename_all = "camelCase")]
pub struct LocDelta {
    pub added: u64,
    pub removed: u64,
}

#[derive(Debug, Clone, Serialize)]
#[serde(rename_all = "camelCase")]
pub struct CodeStats {
    pub total: LocDelta,
    pub by_provider: HashMap<String, LocDelta>,
    pub by_project: HashMap<String, LocDelta>,
    pub top_files: Vec<FileLoc>,
    pub this_week: LocDelta,
    pub this_month: LocDelta,
    pub session_count: u64,
}

#[derive(Debug, Clone, Serialize)]
#[serde(rename_all = "camelCase")]
pub struct FileLoc {
    pub path: String,
    pub delta: LocDelta,
    pub provider: String,
}

pub fn compute_stats() -> CodeStats { /* fan-out across providers + aggregate */ }
```

**File: `src-tauri/src/code_stats/claude.rs`** — re-parses `~/.claude/projects/**/*.jsonl`:
- For each line, deserialize as `serde_json::Value`
- Skip if `message.role != "assistant"`
- Iterate `message.content[]` array
- If `type == "tool_use"`:
  - `name == "Write"` → count newlines in `input.content` → `added += n`
  - `name == "Edit"` → `added += newlines(input.new_string)`, `removed += newlines(input.old_string)`
  - `name == "MultiEdit"` → loop `input.edits[]`, same as Edit per entry
- Capture `timestamp` for week/month bucket
- Capture `cwd` (in the session's first `attachment` line) for project bucket
- Return `Vec<SessionStat>` with per-session breakdown

**File: `src-tauri/src/code_stats/codex.rs`** — re-parses `~/.codex/sessions/**/*.jsonl`:
- Skip non `function_call` events; skip `name != "exec_command"`
- Parse `arguments` as JSON, get `cmd` string
- If `cmd` starts with `apply_patch` (or the redirect `apply_patch <<`), extract the heredoc body
- Find `*** Begin Patch` / `*** End Patch` boundaries; for each line inside:
  - Skip lines starting with `*** ` (file headers) and `+++ `/`--- `/`@@ ` (diff headers, unlikely in codex format but defensive)
  - Lines starting `+` → `added += 1`
  - Lines starting `-` → `removed += 1`
- Capture `timestamp` from outer JSON
- Capture `cwd` from session_meta line (first line of file)

**File: `src-tauri/src/commands/code_stats.rs`**

```rust
use crate::code_stats;

#[tauri::command]
pub async fn compute_code_stats() -> Result<code_stats::CodeStats, String> {
    tauri::async_runtime::spawn_blocking(code_stats::compute_stats)
        .await
        .map_err(|e| format!("compute_code_stats failed: {e}"))
}
```

**Wire-up:**
- `src-tauri/src/lib.rs`: add `mod code_stats;`; append `commands::compute_code_stats` to `invoke_handler`
- `src-tauri/src/commands/mod.rs`: add `pub mod code_stats; pub use code_stats::compute_code_stats;`

**Cache:** in-process `once_cell::sync::Lazy<Mutex<HashMap<PathBuf, (SystemTime, SessionStat)>>>` keyed by file path + mtime. On `compute_stats`, scan all session files; for each, look up cache by `(path, mtime)`; if miss or mtime changed, re-parse and overwrite. **No disk cache in v1.**

## 4. Risks and Mitigations

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Claude session files mix many `attachment` / `last-prompt` / `permission-mode` lines (not `assistant`) — parser slows down on large files | High | Med (latency) | Stream files line-by-line with `BufReader`; skip non-`message` lines cheaply via `type` string check before full deserialization |
| Codex `apply_patch` heredoc can span multiple lines and use various quoting (`<<'EOF'`, `<<EOF`, `<<-EOF`); regex extraction is fragile | High | Med (under-count) | Look for `*** Begin Patch` / `*** End Patch` markers inside the `cmd` string itself — they're literal and reliable; ignore heredoc syntax |
| `MultiEdit` content can be very large; computing `newlines(new_string)` per edit might allocate | Low | Low | Use `bytes.iter().filter(\|&b\| *b == b'\n').count()` to avoid allocation |
| User-bot loop noise: assistant sometimes reads files (Read tool) which is NOT code generation; mistakenly counting Read.content would inflate numbers | Med | High (wrong metric) | Whitelist tool names: only `Write`, `Edit`, `MultiEdit`, `NotebookEdit` count. Anything else (Read/Bash/Glob/etc.) is ignored |
| `cwd` not present in every session line — project bucket would have many "unknown" entries | Med | Low (cosmetic) | Cache the first `cwd` seen per session file; fall back to `"unknown"` label in UI |
| Sessions list cache invalidation: if user resumes a session, file appends but mtime changes — cache catches it ✓ | Low | Low | mtime-keyed cache already addresses this |
| Stats page TTI: first compute on cold cache could be 3-10s for power users | Med | Med (perceived slowness) | Show skeleton; emit progress via Tauri `emit_all("stats_progress", n)` if computation exceeds 2s. **Stretch goal — skip for v1 if simple loading is acceptable.** |
| Gemini exclusion may confuse users who don't read README | Low | Low | Stats page header subtitle: "Showing Claude + Codex. Gemini sessions don't log code edits." |

## 6. Open Questions / Deferred Decisions

These do NOT block v1; they're flagged for future iterations:

1. **Persistent disk cache** — should be added once cold-start exceeds 5s in real usage. Path: `~/.cache/cccode/stats.json` keyed by session file path + mtime.
2. **Charts** — current design uses static bars. Adding a sparkline / timeline would require a charting lib (recharts ~140 KB). Defer to user request.
3. **Filter by file extension** — useful for "only count `.py` files" but adds UI complexity. Defer.
4. **Per-language breakdown** — needs an extension → language map. Defer.
5. **Export to CSV/JSON** — useful for sharing; trivial via Tauri `dialog.save`. Defer until requested.
6. **Tracking *rejected* edits** — currently we count every Write/Edit, even those rejected by the user. To filter, would need to cross-reference next-turn tool_result success. Defer; v1 documents this as "total proposed code" not "accepted code".
